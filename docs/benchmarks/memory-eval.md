# Phase 0 记忆层消融评测与架构裁决报告

> 评测日期：2026-11-22｜评测引擎：`internal/memory/eval`（纯 Go `modernc.org/sqlite` WAL + FTS5 + 连续 `float32` 向量扫描）｜实测向量模型：`Qwen/Qwen3-Embedding-4B`（2560d 原生 vs 1024d Matryoshka）。
> 本报告所有结论均严格基于离线合成基准、在线实测 Embedding 与生产旧库只读快照（已彻底匿名化）的量化数字，服务于 Phase 1 记忆层实现的 KISS 裁剪决策。

## 1. 评测基准与实验设置

### 1.1 30 天熟人群聊合成评测集

代码位置：[dataset.go](../../internal/memory/eval/dataset.go)，确定性生成（零随机漂移）：

- **记忆规模**：**647 条**跨 30 天（`2026-10-23` ~ `2026-11-22`）记忆，含：
  - 6 名熟人群友，每人经历 2~3 次群昵称/外号变更（共 30+ 别名映射至规范实体锚点）；
  - 22 条核心稳定习惯、个人偏好、宠物/据点与多人共同事件；
  - 10 条冲突时序演化链（21 条情景/语义记录，含 2~3 步状态变更与 `t_event` / `superseded_by` 链，如秋招→拿 Offer→入职、搬家、换显卡、改旅游目的地、伤病康复等）；
  - 4 条未合并重复碎片情景记忆（检验 Dreaming 最终事实合并前后差异）；
  - **600 条高干扰水群噪音**（刻意复用真实群友昵称、食物、游戏、硬件、宠物、通勤、天气等高频词面，且对其中 25 条构造高频无关触发回放以验证防马太效应门控）；
  - **469 条 `memory_assoc` 关联边**（按共享规范实体与 2 小时会话邻近自动构建，无手工针对查询作弊边）。
- **标注查询（48 条，5 类）**：
  - `direct`（10 条）：词面与实体直接命中的偏好/习惯查询；
  - `associative`（10 条）：高度口语化的熟人群聊隐喻/多线索联想查询（不出现记忆原文关键词，如“别放那种绿油油气味冲的配菜”、“橘色毛球又踩键盘”）；
  - `nickname_drift`（10 条）：使用群友新/旧变更昵称提问，而记忆正文存储的是历史昵称；
  - `temporal`（10 条）：询问最新状态，旧状态带有高词面重叠与历史召回记录；
  - `noise_rejection`（8 条）：纯水群闲聊（无匹配记忆，期望沉默返回 0 条）。

### 1.2 核心指标定义

代码位置：[metrics.go](../../internal/memory/eval/metrics.go)：

- **`Recall@4`**：正样本查询（40 条）Top-4 召回率均值；
- **`MRR`**：正样本查询首条命中倒数排名均值；
- **`Temporal Accuracy (TempAcc)`**：时序查询（10 条）中最新状态严格排第 1 且压过所有被取代旧状态的比例；
- **`Superseded Leak (Leak)`**：时序查询 Top-4 中泄露已被 `superseded_by` 取代旧记忆的比例；
- **`Noise Rate (Noise)`**：8 条纯水群噪音查询中错误浮出 `>=1` 条记忆的误触发率（越低越好）；
- **`Distractor Rate (DistRt)`**：所有返回槽位中非期望条目的占比（越低越干净）。

### 关键归因解读

1. **旧版纯向量方案（`V0-PureVec2560`）全面落后**：`TempAcc` 仅 **0.100**（90% 返回过期旧状态），`Leak = 1.000`，`Noise = 1.000`，昵称漂移召回率仅 **0.600**，充分复现了设计文档指出的四大痛点。
2. **`B0 → B1`（衰减与防马太强化）**：`Noise` 从 **1.000 骤降至 0.250**，`DistRt` 从 **0.829 降至 0.589**，`TempAcc` 由 **0.400 → 0.600**。低重要度旧水群噪音衰减后自然跌破阈值。
3. **`B1 → B2`（显式时序 `superseded_by` 与合并）**：`Superseded Leak` 彻底归零（**0.700 → 0.000**），`TempAcc` 提升至 **0.800**，`MRR` 升至 **0.713**。逐条核查剩余 2 条未排第 1 的时序查询（`q_tmp_02`、`q_tmp_03`）发现：**均无任何旧状态泄露**，最新状态稳居 Top-2，排第 1 的是同一群友的非冲突互补核心习惯（如“主打 CS2 与瓦罗兰特”排在“改打烟位幽影”之前），属于合理互补而非时序错乱。
4. **`B2 → B3`（弱实体锚点与别名归并）**：**昵称漂移召回率从 0.800 跃升至 1.000（满分）**，`TempR4` 升至 **1.000**，`Noise` 进一步压低至 **0.125**。但对于不含关键词的纯口语联想（`Assoc`），纯词面+锚点仅 `0.200`。
5. **`B3 → B4`（并发向量双路种子）**：口语化联想召回率（`Assoc`）从 **0.200 飙升至 0.800（+0.600）**，整体 `Recall@4` 达到 **0.950**、`MRR` 达到 **0.871**。逐条核查 `B4` 仅存的 3 条噪音误触发（`q_noi_02/04/07`）全部命中了低重要度（`imp=2~4`）的近似水群噪音（降温刮风、地铁挤、快递驿站），说明**写入期蒸馏过滤低价值水群废话**比无限拉高检索阈值更治本。

## 3. 子消融实验：裁决核心设计待定项

### 3.1 2560-dim 原生 vs 1024-dim Matryoshka（`Qwen/Qwen3-Embedding-4B`）

| 维度 | 正样本 Top-1 余弦 (min / p50 / max) | 噪音 Top-1 余弦 (min / p50 / max) | 默认工作点 `Recall@4 / MRR / Assoc` | 控噪工作点 (`s=0.50, t=0.54`) `Recall@4 / MRR / Noise` | 1 万条内存 | 1 万条 4 核扫描均值 |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **2560d** | `0.567 / 0.758 / 0.929` | `0.482 / 0.558 / 0.706` | `0.900 / 0.825 / 0.600` | `0.875 / 0.800 / 0.125` | 97.66 MB | 1.84 ms |
| **1024d** | `0.586 / 0.778 / 0.930` | `0.503 / 0.586 / 0.733` | **`0.950 / 0.871 / 0.800`** | **`0.900 / 0.821 / 0.125`** | **39.06 MB** | **0.67 ms** |

- **结论**：**1024d Matryoshka 在精度上全面持平甚至反超 2560d**（默认工作点 `Recall@4 +0.050`、`MRR +0.046`、`Assoc +0.200`；控噪工作点同样领先），同时**内存与 SQLite 体积直降 60%、扫描提速 2.7×、API 批量传输提速 ~2×**（647+48 条首次嵌入 `4.87s` vs `10.22s`）。

### 3.2 衰减函数（指数 vs 幂律）与防马太强化

| 变体 | Recall@4 | MRR | TempAcc | Noise | DistRt |
| :--- | :---: | :---: | :---: | :---: | :---: |
| `B2-exponential` | 0.750 | 0.713 | 0.800 | 0.250 | 0.583 |
| `B2-power_law` | 0.750 | 0.713 | 0.800 | 0.250 | **0.577** |
| `B3-exponential` | 0.800 | 0.667 | 0.800 | 0.125 | 0.742 |
| `B3-power_law` | **0.825** | **0.700** | 0.800 | 0.125 | **0.736** |
| `B1-AntiMatthew` | 0.750 | 0.688 | 0.600 | 0.250 | **0.589** |
| `B1-NaiveCount` | 0.750 | 0.688 | 0.600 | 0.250 | 0.600 |

- **衰减函数**：30 天跨度内两者指标接近，`power_law` 凭借更平缓的长尾保留在 `B3` 上带来 `+0.025 Recall@4 / +0.033 MRR` 微弱优势，且公式同样只有 1 行无额外状态，可优先采用 `power_law`（或 `exponential`，二者皆极简）。
- **防马太门控**：未设门控的 `NaiveCount` 会将高频误触发噪音条目的 `recall_count` 从 `0` 刷至 `6`，使其检索强度膨胀 **~3×** 并增加干扰占比（`DistRt` 恶化 `+0.011`）。门控仅需检查 `BotReplied && Relevant` + 30 分钟冷却窗口，实现成本极低，必须保留。

### 3.3 关联扩散跳数（`0-hop` vs `1-hop` vs `2-hop`）——关键反直觉发现

| 配置 | Recall@4 | MRR | TempAcc | Noise | DistRt |
| :--- | :---: | :---: | :---: | :---: | :---: |
| `B3-hops=0`（仅实体锚点，无图扩散） | 0.800 | **0.717** | **0.900** | 0.125 | **0.714** |
| `B3-hops=1`（+ 1 跳 `memory_assoc`） | 0.800 | 0.667 | 0.800 | 0.125 | 0.742 |
| `B3-hops=2`（+ 2 跳 `memory_assoc`） | 0.800 | 0.654 | 0.800 | 0.125 | 0.742 |
| `B4-2560-hops=0` (`s=0.50, t=0.48`) | 0.875 | 0.796 | 0.800 | 0.125 | **0.688** |
| `B4-2560-hops=1` (`s=0.50, t=0.48`) | 0.875 | 0.800 | 0.800 | 0.125 | 0.731 |
| `B4-2560-hops=2` (`s=0.50, t=0.48`) | 0.875 | 0.796 | 0.800 | 0.125 | 0.731 |
| `B4-1024-hops=0`（默认工作点） | **0.950** | **0.871** | 0.800 | 0.375 | **0.716** |
| `B4-1024-hops=1`（默认工作点） | **0.950** | **0.871** | 0.800 | 0.375 | 0.738 |

- **实测裁决**：
  - **2 跳扩散在所有配置下均严格负收益**（`MRR` 下降、`DistRt` 上升），**直接删除**。
  - 更重要的是，当**弱实体锚点（`memory_entities` + `AliasMap`）+ 并发向量双路种子**同时存在时，**1 跳 `memory_assoc` 扩散并未带来可观测的 `Recall@4` 增益（`0.950 → 0.950`）**，反而因同人物不同话题记忆互相泄露激活导致 `DistRt` 恶化 `+0.022 ~ +0.043`（并在 `B3` 上拉低 `MRR -0.050`、`TempAcc -0.100`）。

### 3.4 `MinVectorSim` × `SurfaceThreshold` 阈值扫描（1024d 摘要）

| `MinVectorSim` | `SurfaceThreshold` | Recall@4 | MRR | Assoc | Noise | DistRt |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| `0.46` | `0.42` | **0.950** | **0.871** | **0.800** | 0.375 | 0.738 |
| `0.50` | `0.48` | 0.900 | 0.821 | 0.600 | 0.250 | 0.733 |
| `0.50` | `0.54` | 0.900 | 0.821 | 0.600 | **0.125** | **0.719** |
| `0.54` | `0.54` | 0.875 | 0.796 | 0.500 | **0.125** | **0.715** |

推荐线上起点：**被动联想取保守控噪工作点（`minSim=0.50, surface_threshold=0.54`）**，避免水群误触发；**主动工具 `memory_recall` 取高召回工作点（`minSim=0.46, surface_threshold=0.40`）**。

## 5. 真实生产旧库快照只读体检（354 条 Mem0 + 5,000 条时间线）

只读分析来源：`data/legacy_snapshot/`（所有用户名与 QQ 号均已彻底脱敏为 `User_1`~`User_6`）。

### 5.1 量化失效模式审计

| 失效维度 | 真实快照实测数据 | 根因与对新设计的启示 |
| :--- | :--- | :--- |
| **零合并 / 零取代** | `updated_at != created_at` 为 **0 / 354**（`mem0_history.db` 270/270 全为 `ADD`） | 旧版 Mem0 从未收敛任何重复或演进状态 |
| **高度近重复膨胀** | 余弦 `>=0.90`：**33 对**；`>=0.85`：**212 对**（波及 **135/354 = 38.1%** 条目）；`>=0.80`：**696 对**（波及 **64.4%** 条目） | 同一事件（如 `User_4` 转为夜班）在 4 天内重复写入 4 条余弦 `0.943~0.971` 的高度雷同记忆 |
| **背景余弦塌缩（各向异性）** | 全部 354 条两两余弦 **均值 `0.5389`、p50 `0.5275`、p95 `0.7269`** | **99.2% (351/354)** 条目以冗长样板开头（`群聊成员“XXX”（QQ: ...）于2026年11月XX日表示...`），严重抬高无关记忆的余弦基底！新库正文必须精炼去样板，QQ 号与日期改存结构化列 |

### 5.2 真实数据检索对照核验（5 个匿名化真实主题探针）

| 探针主题 | 旧版平铺 Top-4 (`top1 sim` / Top-4 内 `>=0.85` 重复对数) | 加阈值 + 去重 Top-4 (`count` / `top1 sim`) | 现象说明 |
| :--- | :---: | :---: | :--- |
| `night_shift`（`User_4` 夜班状态） | `0.626` / **6 对（满额 4/4 全重复！）** | `4` / `0.626`（0 重复对） | 旧版 Top-4 被同一夜班事件的 4 条重复记忆完全占满 |
| `gpu_status`（`User_4` 显卡状态） | `0.569` / 1 对 | `4` / `0.569`（0 重复对） | 避免旧状态重复占据多个上下文槽位 |

## 6. KISS 架构保留 / 裁剪最终建议

严格遵循「无量化收益的复杂度一律删除」原则，对 `docs/design/memory.md` 的 Phase 1 实现给出明确裁决：

| 组件 / 机制 | 裁决 | 实测依据 |
| :--- | :---: | :--- |
| **SQLite WAL + FTS5（纯 Go 双字切分）** | **保留（必选）** | 无 CGO、`p95 ~0.5 ms`，词面精确召回 `Direct = 1.000` |
| **衰减 + 防马太有效强化** | **保留（必选）** | `Noise 1.000 → 0.250`、`DistRt -0.240`，防高频误触发噪音强度膨胀 `3×`；优先 `power_law`（与指数同等简单且长尾略优） |
| **显式时序 `t_event` + `superseded_by` + Dreaming 合并** | **保留（必选）** | `Superseded Leak 1.000 → 0.000`、`TempAcc 0.400 → 0.800`；直接根治旧库 38.1% 近重复膨胀 |
| **弱实体锚点 + `AliasMap` 别名归并（`memory_entities`）** | **保留（必选）** | 昵称漂移召回 `0.800 → 1.000`（真实 10 天数据已有 33% 成员改昵称），无需正文硬塞 QQ 号 |
| **并发向量双路种子（1024d Matryoshka + 纯 Go 连续切片扫描）** | **保留（必选）** | 口语联想 `Assoc 0.200 → 0.800`、总 `Recall@4 → 0.950`；1024d 反超 2560d 且省 60% 内存；1 万条 4 核 `p99 = 1.51 ms` |
| **去除冗长样板正文（如 `群聊成员“X”（QQ:...）于...`）** | **新增铁律** | 旧库样板导致无关记忆余弦均值高达 `0.539`，精炼短句存储可显著拉开正负样本余弦间距 |
| **2560 维全量存储** | **裁剪（Drop）** | 1024d Matryoshka 精度更高（`+0.050 Recall@4`）、内存减 60%、扫描快 2.7× |
| **`sqlite-vec` / Qdrant 外部向量库** | **裁剪（Drop）** | 纯 Go 连续 `[]float32` 扫描在 1 万条内 `<1.5 ms p99`，零 CGO 与运维成本 |
| **2 跳 `memory_assoc` 扩散** | **裁剪（Drop）** | 全线负收益（`MRR` 降低、`DistRt` 恶化） |
| **1 跳 `memory_assoc` 关联图扩散** | **Phase 1 延后（Defer）** | 在 `B4-1024` 上相比 `0-hop` 无任何 `Recall@4`/`MRR` 增益（`0.950 / 0.871` 持平）却增加 `+0.022 DistRt` 与 Dreaming 构图复杂度；仅当真实上线日志暴露出“锚点+向量仍漏召回的多跳案例”时再按需引入 |
