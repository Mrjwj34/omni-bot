## 6. 首轮实测发现与校准闭环

在 Phase 0 首次实测（首轮默认参数 `η=(0.32,0.36,0.30), τ=(18m,10m,14m)`、单块 `<recent_group_chat>` 未切分最新消息）中发现三项可直接指导生产落地的真实工程规律，并在本报告对应的校准版中闭环验证：

1. **防正反馈锚定（Decisions API 关键陷阱）**：若直接将 `<inner_feeling>` 与整个 6 条历史窗口混排为单一 `<recent_group_chat>`，模型容易把既有的高涨心境及数轮前的出货消息重复计入 `δP/δA/δD`，导致连发 4 条消息即顶死 `P=+1.00, A=+1.00` 且后续调侃/晚安轮仍残留正偏置。改为显式拆分 `<earlier_context>` + `<latest_message>`，并在三个 `score` rubric 中要求仅评估 `<latest_message>` 的即时新增刺激、忽略 `<current_inner_feeling>` 底色后，轨迹恢复清晰回落与多象限切换。
2. **高频群聊敏感度与半衰期校准**：熟人群聊常在 20~60 秒内连续刷出多条高能消息，敏感度从 `(0.32, 0.36, 0.30)` 下调至 `(0.18, 0.22, 0.18)`、半衰期从 `(18m, 10m, 14m)` 收紧至 `(12m, 6m, 10m)`、死区半径定为 `0.18`，消除快速饱和顶死，同时保持深夜停顿后自然回落。
3. **bk101 身份边界在第一人称中的精准保真**：首轮盲评中 Arm B 在 `ab01_loot_hype` 高激活态下出现了一句粗口（“卧槽牛逼”），根因是第一人称信念层弱化了旧人设里的“少女群友 / 说话干净绝不飙脏话”约束。补齐该原生第一人称自我约束（零硬脚本、零上帝视角标签）后，消除 OOC 风险并保持自然松弛口吻。

## 7. 工程落地建议（供后续 Phase 1/2 复用）

1. **Decisions API 并行挂车方案定型**：单次 `client.Decisions.Create`（`operations.WithRetries(retry.Config{Strategy: "none"})`）同时评估 `should_reply`（`noul`）与 `delta_P`/`delta_A`/`delta_D`（5 档 `score`，`(score-2)/2` 归一化），严格 `0` 输出 Token；输入必须物理拆分 `<earlier_context>` 与 `<latest_message>`，防止历史峰值重复计分。
2. **PAD 动力学参数与 30 原型定稿**：`internal/persona/pad` 已通过离线单测与 25 轮长对话仿真验证；静息基线 `(0.12, 0.02, 0.02)`、敏感度 `(0.18, 0.22, 0.18)`、半衰期 `(12m0s, 6m0s, 10m0s)` 与死区半径 `0.18` 既保留鲜明情绪起伏，又确保自然回落零漂移。
3. **bk101 无缝迁移与缓存友好布局**：冻结第一人称自我观念 + 9 条原子性格条目放在静态 `system_instruction`，动态 `<inner_feeling>` 严格置于单轮 Turn 输入中（死区内完全省略），与无状态 `step_list`（`store: false`）天然兼容。
