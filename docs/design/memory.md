# 记忆层与 Dreaming 设计方案

> 方案严格遵循 KISS 与实测优先原则。所有结构组件与打分项必须通过模拟群聊评测基线验证；不能提升指标的复杂度一律移除。

## 1. 背景与核心问题

旧版基于 Mem0 + Qdrant 的平铺方案存在四个结构性痛点：

1. **纯向量平铺稀释**：开源版 Mem0 仅依赖单路余弦相似度 Top-K，缺乏词面/实体精确匹配、关联共振与权重分层；当日常流水账堆积后，关键长期事实（如身份、关系、固定习惯）极易被噪音挤出召回窗口。
2. **缺少时序与最终事实收敛**：无法区分两段矛盾记忆的先后顺序，写入时的短视 `UPDATE` 容易误覆盖核心旧信息，相对时间（如“昨天”“下周五”）过境后直接失效。
3. **缺少强化与遗忘循环**：所有记忆永久平权，不会随有效召回加深印象，也不会因长期无人提及自然淡忘，导致库容信噪比随时间单调劣化。
4. **读写锁阻塞**：后台归档持有粗粒度锁跨越慢速 LLM/网络调用，导致实时对话检索频繁跳过或超时返回空。

## 2. 核心设计原则

1. **正面解决通用召回，不靠特判“逃课”**：不通过硬编码“按发言人 QQ 号强塞静态身份卡”绕过召回问题，而是建设通用的多线索联想与排序体系；高重要度、高连接度的核心身份与习惯记忆应在统一通路中自然稳定胜出。
2. **不强绑账户，弱类型实体锚点**：记忆锚点涵盖人（QQ 号、真名、外号、曾用群昵称归并）、群黑话、游戏、事件、地点等规范化字符串，由巩固期维护别名归并，不设重型本体与关系类型系统。
3. **日志为源，SQLite 自持**：原始群聊时间线只追加不改写；记忆表、FTS5 全文索引、向量索引与关联图均落在本地 SQLite（WAL 模式），活跃检索集常驻内存，彻底移除 Mem0 与独立向量/图数据库依赖。
4. **写入时智能，读取时轻量**：语义蒸馏、相对时间绝对化、别名归并、冲突取代、关联边重算与遗忘清理全部放在后台异步巩固（Dreaming）阶段，绝不阻塞实时聊天热路径。
5. **显式时序与最终事实合并**：每条记忆记录真实事发时间 `t_event` 与时效取代链 `superseded_by`，整理期将演化中的旧事实收敛为最新最终事实。
6. **评测先行，可证伪推进**：先建模拟群聊基准与最简基线，后续每引入一项机制（衰减、联想扩散、向量种子、合并整理）必须跑出量化增益才保留。

## 3. 记忆模型与存储草案

面向熟人群聊生活流，去掉面向 Code Agent 的程序性/多域隔离复杂度，记忆收敛为两类：

| 类别 (`kind`) | 内容 | 典型来源 |
| :--- | :--- | :--- |
| `episodic`（情景） | 在特定时间发生过的具体事件、互动经过与状态变更 | 闲时从对话片段蒸馏 |
| `semantic`（语义） | 从情景归纳沉淀出的稳定事实、个人偏好、固定习惯、人际关系与群黑话 | Dreaming 阶段合并与提炼 |

### 3.1 SQLite 核心表结构

```sql
CREATE TABLE memories (
    id            TEXT PRIMARY KEY,
    kind          TEXT NOT NULL,              -- episodic | semantic
    text          TEXT NOT NULL,              -- 单句清晰陈述，含绝对时间语义
    t_event       INTEGER NOT NULL,           -- 事发时间戳（Unix 秒，非入库时间）
    t_ingest      INTEGER NOT NULL,           -- 入库时间戳
    superseded_by TEXT NOT NULL DEFAULT '',   -- 被新事实取代时指向新记忆 id
    importance    INTEGER NOT NULL,           -- 1~10，蒸馏/整理期评定
    strength      REAL NOT NULL,              -- 动态检索强度（衰减与强化见第 5 节）
    last_recalled INTEGER NOT NULL DEFAULT 0, -- 最近一次有效召回时间
    recall_count  INTEGER NOT NULL DEFAULT 0, -- 有效召回次数
    archived      INTEGER NOT NULL DEFAULT 0, -- 0=活跃索引 | 1=已归档退出热集
    provenance    TEXT NOT NULL DEFAULT '[]'  -- 来源消息 seq_id 列表 JSON
);

CREATE TABLE memory_entities (
    memory_id TEXT NOT NULL,
    entity    TEXT NOT NULL,                  -- 规范化实体锚点（经别名归并）
    PRIMARY KEY (memory_id, entity)
);
CREATE INDEX idx_memory_entities_entity ON memory_entities(entity);

CREATE TABLE memory_assoc (
    a          TEXT NOT NULL,                 -- 记忆 id，约定 a < b
    b          TEXT NOT NULL,
    weight     REAL NOT NULL,                 -- 0~1，无类型关联强度
    last_fired INTEGER NOT NULL,
    PRIMARY KEY (a, b)
);
```

另配一张 `FTS5` 虚表覆盖 `memories.text` 与 `entity`，以及向量存储（`sqlite-vec` 或 SQLite `BLOB` + 内存切片并发点积，视 Go 基准实测择简）。

## 4. 时序与事实收敛

1. **相对时间绝对化**：蒸馏 Prompt 必须注入每条消息的真实日期时间戳，强约束模型把“昨天”“下周五”“上个月”换算为绝对日期写入 `t_event` 与记忆正文，避免跨月召回产生时间错乱。
2. **时效链（`superseded_by`）**：整理期对同一实体锚点的新旧记忆执行三分判定：
   - **新增**：无冲突的新信息，直接入库；
   - **取代**：状态发生变更（如“准备考研”→“已入职某公司”），新建最新事实并将旧记忆的 `superseded_by` 指向新 id。被取代记忆默认退出召回并加速衰减，但保留时间链可供显式追溯历史；
   - **合并为最终事实**：多条分散重复的情景记忆（如多次不同时间出现同一习惯或偏好）合并归纳为一条精炼的 `semantic` 最终事实，继承累计权重与来源溯源。
3. **统一时间戳呈现**：所有进入模型上下文的记忆统一附带 `t_event` 时间前缀（例如 `[2026-11-18]`），让模型直接感知事件先后。

## 5. 召回、强化与遗忘机制

### 5.1 双通道召回

* **被动联想（常开，无触发门控）**：
  1. **提取种子线索**：从本轮新消息提取发言人规范锚点、关键词/实体词（以及待实测评估的并发向量 Top-K 种子），命中初始种子记忆；
  2. **关联扩散与多线索交汇共振**：沿内存中的 `memory_assoc` 邻接表扩散 1~2 跳（带每跳衰减系数）。当发言人线索与话题线索在同一条记忆（例如“某人不吃香菜”或“某人核心身份”）处交汇时，激活分自然叠加胜出；
  3. **综合排序与过滤**：结合激活分与 `strength` 排序，低于 `surface_threshold` 沉默；已在当前滑动上下文窗口内注入过的记忆去重跳过；按条数与 token 预算截断注入。
* **主动回忆（Tool：`memory_recall`）**：
  - 供主模型显式翻旧账、查某段时间或冷归档记忆；
  - 融合 FTS5 词面分、向量语义分、`strength` 与可选时间范围过滤（`after` / `before` / `include_archived`）。

### 5.2 有效召回强化与防马太效应死循环

* **强度衰减**：`strength` 随距 `max(t_ingest, last_recalled)` 经过的时间下降；`importance` 越高、`recall_count` 越多，衰减越平缓；被 `superseded_by` 取代的记忆衰减速率加倍。
* **防止误召回自我强化**：绝不能“只要塞进上下文就 `recall_count + 1`”，否则泛化废话会靠高强度无限霸榜。强化必须满足：
  1. 当轮 Bot 实际产生有效回应（非沉默跳过）；
  2. 记忆在当轮属于高相关命中（或在后台被判定确实被回复所利用/呼应）；
  3. 同一记忆在短时间连续对话冷却窗口内（如 30 分钟）最多计 1 次强化。

### 5.3 遗忘（预算内置换）

* 活跃索引维持有界容量上限，防止长期使用后噪声淹没信号；
* 后台 Dreaming 定期将低 `strength`、长期未召回的碎片情景记忆标记 `archived = 1` 移出内存热索引；
* 归档超过保留期（如 180 天）后物理删除派生记忆行（原始聊天时间线不受影响，随时可重放重建）。

## 6. 后台 Dreaming 流程

分为两个异步节奏，均不阻塞实时交互：

1. **浅层蒸馏（闲时触发）**：群聊静默一段时间或累计达批次阈值后，将未归档对话切片蒸馏为带绝对 `t_event`、规范锚点与 `importance` 的候选情景记忆并入库。
2. **深层 Dreaming（周期触发，如每日低峰或按累计归档量）**：
   - 实体别名归并（同一人的新旧群昵称、外号、QQ 标识收敛）；
   - 高相似簇合并与三分判定（新增 / 取代写 `superseded_by` / 合并为最终 `semantic` 事实）；
   - 依据共享锚点、时间邻近与语义相似重算 `memory_assoc` 边权；
   - 执行衰减结算、低强记忆归档与超期清理；
   - 为人格层提供沉淀后的高强度记忆快照（见 [persona-and-emotion.md](persona-and-emotion.md)）。

## 7. 阶段 0：评测先行与待实测变量

在接入主 Bot 运行时前，先独立构建离线回放评测集，所有参数与机制以数字验收：

* **模拟熟人群聊基准集**：覆盖多群友长期对话、**群昵称多次变更**、高频稳定习惯 vs 一次性日常碎事、前后冲突的状态变更（检验时效取代与合并），并混入 **500~1000 条高语义干扰水群噪音**。
* **核心指标**：
  - 主动/综合召回：`Recall@K`、MRR、时效更新准确率（不返回已被取代的旧事实）；
  - 被动联想三指标（借鉴 REI）：**引用率**（注入后被回复实际使用的比例）、**噪声率**（注入但与当轮无关的比例）、**反事实胜率**（带注入 vs 不带注入盲评胜率）；
  - 性能：被动通路 p99 延迟、长回放后活跃集规模稳定性。
* **待通过消融实验直接裁决的关键问题**：
  1. **纯词面/实体锚点扩散 vs 实体锚点 + 与 System 1 并发计算的向量双路种子**——验证在口语化极强的 QQ 群聊中，增加并发向量种子带来的 Recall 增益与噪声代价；
  2. 衰减函数形式（幂律 vs 指数）、`surface_threshold` 与扩散跳数（1 跳 vs 2 跳）的实测最简最优值；
  3. 向量索引在目标规模（数千至数万条）下用内存切片扫描 vs `sqlite-vec` 的延迟与维护成本对比。
